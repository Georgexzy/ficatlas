# FicAtlas — crawler policy
#
# This matters more here than on a typical site, for two reasons.
#
# 1. Search URLs are an infinite space. Every combination of q, fandoms, tags,
#    ratings, sort and page is a distinct URL backed by a query over 19.7M rows.
#    A crawler that follows filter links will generate unbounded work against a
#    database running on a home connection. That is the classic crawler trap and
#    it is the single most likely way this site falls over.
#
# 2. The reader serves other people's fanfiction in full. Those authors posted
#    to AO3 and FFN, not here, and did not agree to their work appearing under
#    this domain in Google results. Keeping /story/*/chapter/* out of the index
#    is a courtesy that costs nothing — people who want to read arrive through
#    search on this site, not through a search engine landing mid-chapter.
#
# Story detail pages are allowed: they are metadata plus a link to the original,
# which is the part worth being findable and is also what makes the index useful
# to someone who has not heard of it.

# ONE GROUP, NO BLANK LINES INSIDE IT. This is a rule about the file format and
# not about crawling, and it is load-bearing.
#
# RFC 9309 (2022) says a group runs from a User-agent line to the next one and
# that empty lines mean nothing. The 1994 draft it replaced said the opposite:
# records are separated by blank lines. Parsers written to the older reading are
# still in wide use — Python's own urllib.robotparser is one — and on this file
# as it was previously written they saw NOTHING for `*`: the blank line that sat
# directly under `User-agent: *` ended the group before its first rule, so every
# Disallow below was attributed to no agent and dropped, Crawl-delay included.
#
# Google, Bing and Amazon all read it correctly (Amzn-SearchBot arrives once
# every 10.0 seconds, so it is certainly reading the Crawl-delay at the bottom).
# The crawlers that would use a naive parser are the small ones — exactly the
# ones this file's `Disallow: /*?` exists to keep out of the infinite search
# space, and exactly the ones least likely to be missed if they fall in.
#
# Comments are safe anywhere and do the spacing work instead. Blank lines BETWEEN
# groups are correct and required under both readings; keep those.
User-agent: *
# Private and app-only routes.
Disallow: /account
Disallow: /library
Disallow: /login
Disallow: /settings
Disallow: /api/
# Owner-only. Gated server-side, but there is no reason for it to be crawled.
Disallow: /admin
# Full text of works hosted here. See note 2 above.
Disallow: /story/*/chapter/
# The infinite space. `/?q=` and friends are search results, not content.
Disallow: /*?
Allow: /$
Allow: /story/
# Fandom hubs — the only route a crawler has into the index.
#
# Story pages were allowed above long before anything linked to them: search
# results are the sole path to a work, they live at `/?q=` URLs, and those are
# blocked directly above. So /story/ was permitted and unreachable at the same
# time, which is the state this fixes.
#
# The hubs are a bounded alternative to a sitemap of all 19.9M works: a few
# thousand pages, each listing a capped set of works, rather than an invitation
# to crawl the whole index off a home connection. See backend/fandom_hubs.py.
Allow: /fandoms
Allow: /fandom/
# Ship hubs — the same thing again, one per romantic pairing.
#
# Bounded the same way (a few thousand pages, each capped at 50 works per
# archive) and added for a different reason: the fandom hubs compete for
# "[fandom] fanfiction", which AO3 already owns, while pairings are the queries
# readers actually type and are where a cross-archive index has something to say
# that no single archive's tag page can. See backend/ship_hubs.py.
Allow: /ships
Allow: /ship/
Allow: /sitemap.xml
# Politeness. Google ignores this; most other crawlers honour it, and those are
# the ones most likely to crawl without restraint.
#
# It is doing real work and can be measured doing it. Over one day of nginx logs
# Amzn-SearchBot arrived exactly once every 10.0 seconds — pinned to this number
# to the tenth of a second. Applebot, which Apple documents as honouring
# Crawl-delay, arrived once every 3.5 seconds and is the largest single consumer
# of this site. So: the directive is live, and it is a request, not a limit.
Crawl-delay: 10
# Training crawlers get nothing. The index is assembled from other archives, and
# the works in it are not ours to hand over in bulk — the same position the OTW
# takes for AO3.
#
# This list was six agents and had drifted. Cloudflare Radar's May 2026 figures
# put Amazonbot at 3.23% of AI crawler traffic, Meta-ExternalAgent at 3.22% and
# Applebot-Extended at 2.98% — all larger than several agents already named here,
# and none of them listed. A blocklist that names GPTBot and misses Amazonbot is
# not the position it claims to be.
#
# Two things worth knowing about this list rather than treating it as magic:
#
#   * Google-Extended and Applebot-Extended are not crawlers. They are opt-out
#     tokens with nothing behind them — blocking them does not stop a fetch, it
#     changes what Google and Apple may do with pages their ordinary crawlers
#     already have. Included for that reason, not as traffic control.
#   * Bytespider and Meta's agents are widely reported not to honour robots.txt
#     reliably. Nothing here enforces anything; it is a request. If that matters,
#     it has to be an edge rule — Cloudflare has a one-click AI-scraper block,
#     and the tunnel in docker-compose.prod.yml is where that would apply.

# Retrieval agents, which fetch a page because a person asked a question rather
# than to train on it. Blocking these is a genuinely different decision from the
# list above: it costs discovery, since it is how the site would be cited in an
# AI answer. They are blocked anyway, because AO3 blocks ChatGPT-User and this
# file claims to hold the OTW's position — and because the works being fetched
# are not ours to serve into someone else's product, whatever the purpose.
User-agent: ChatGPT-User
Disallow: /

# SEO-audit crawlers, which are a third category again and are blocked for a
# reason that has nothing to do with either of the two above.
#
# These exist to sell backlink and keyword reports about other people's sites.
# They send no readers — there is no product behind them that anybody searches
# on — so every request is cost with no matching benefit. That would be tolerable
# if the cost were small. It is not, and the numbers are worth writing down
# because they are the entire argument:
#
#   over one day of nginx logs, SemrushBot made 7,287 requests, 7,024 of them
#   story pages. That is 17.9% of every story page this site served. Googlebot,
#   over the same day, made 52 requests in total.
#
# An auditing crawler doing 140x the volume of the search engine that actually
# sends people here, against a database on a home connection, is the clearest
# case for a Disallow this file has. SemrushBot fetched robots.txt 70 times that
# day, so it is reading this and will honour it.
#
# The rest are named pre-emptively rather than in response to measurement: none
# of them has appeared in the logs yet, all are the same kind of thing, and the
# alternative is discovering each one by watching a load spike. They cost a line
# each.
#
# Not blocked here, deliberately: Applebot and Amzn-SearchBot, which between
# them are most of the crawl load. Those are search crawlers with a search
# product behind them, so their traffic buys discovery even though this site has
# never had a visitor from either. That is a bet; the SEO auditors are not.
User-agent: SemrushBot
Disallow: /

Disallow: /

Disallow: /
